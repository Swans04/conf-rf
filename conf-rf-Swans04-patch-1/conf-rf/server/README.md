# Серверная часть проекта «Конференции.РФ»

Эта папка — справочная. Ничего из неё не подключается к браузеру
и не запускается как программа. Здесь лежит описание структуры базы
данных, формальная схема таблиц и демонстрационные данные —
то, что клиенту (обычному пользователю) видеть не нужно.

Рабочая (клиентская) часть находится в соседней папке `../client/`
и открывается двойным щелчком по файлу `index.html`.

## Таблицы

### 1. User — Пользователи

| Поле       | Тип                 | Ключ | Описание                        |
|------------|---------------------|------|---------------------------------|
| id         | Счётчик             | PK   | Уникальный идентификатор        |
| login      | Текстовый (80)      | UQ   | Логин (латиница и цифры)        |
| password   | Текстовый (200)     |      | Хеш пароля                      |
| full_name  | Текстовый (100)     |      | ФИО (кириллица и пробелы)       |
| phone      | Текстовый (20)      |      | Телефон 8(XXX)XXX-XX-XX         |
| email      | Текстовый (120)     | UQ   | Адрес электронной почты         |
| is_admin   | Логический (Да/Нет) |      | Признак администратора          |

### 2. Room — Помещения

| Поле       | Тип                 | Ключ | Описание                        |
|------------|---------------------|------|---------------------------------|
| id         | Счётчик             | PK   | Уникальный идентификатор        |
| name       | Текстовый (100)     | UQ   | Название помещения              |
| capacity   | Числовой (целый)    |      | Вместимость (человек)           |

### 3. Booking — Заявки

| Поле             | Тип             | Ключ | Описание                              |
|------------------|-----------------|------|---------------------------------------|
| id               | Счётчик         | PK   | Уникальный идентификатор              |
| user_id          | Числовой        | FK   | Ссылка на User(id)                    |
| room_id          | Числовой        | FK   | Ссылка на Room(id)                    |

| created_at       | Дата/время      |      | Когда заявка была создана             |

### 4. Review — Отзывы

| Поле         | Тип                 | Ключ    | Описание                        |
|--------------|---------------------|---------|---------------------------------|
| id           | Счётчик             | PK      | Уникальный идентификатор        |
| booking_id   | Числовой            | FK, UQ  | Ссылка на Booking(id)           |

## Связи между таблицами

Нотация «воронья лапка» (как в Microsoft Access):
User (1) ──────< (M) Booking
один пользователь может иметь много заявок

Room (1) ──────< (M) Booking
одно помещение может фигурировать во многих заявках

Booking (1) ─── (1) Review
одна заявка — не более одного отзыва
(поле Review.booking_id уникально)

## Замечания по Microsoft Access

- **Типы данных.** Первичные ключи — «Счётчик» (AutoNumber).
  Текстовые поля — с указанием размера. Даты — «Дата/время».
  Логические — «Логический» (Да/Нет).
- **Целостность данных.** При создании связей в окне «Схема данных»
  установите флажок «Обеспечение целостности данных».
- **Каскадное удаление.** Для связи Booking – Review можно включить
  «Каскадное удаление связанных записей».
- **Индексы.** Уникальные на `User.login` и `User.email`.
  Составной индекс `(room_id, start_datetime)` в Booking —
  для предотвращения конфликтов бронирования.
- **Порядок создания в Access.**
  1. Новая база данных.
  2. «Конструктор» → создать все 4 таблицы.
  3. «Работа с базами данных» → «Схема данных».
  4. Перетащить первичные ключи на внешние ключи.
  5. Включить обеспечение целостности.
  6. Сохранить схему.
